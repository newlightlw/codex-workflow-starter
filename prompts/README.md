# 7 组可复制提示词

以下是整理版模板，替换方括号，并给出你项目中的真实文件路径。仓库未打包的可选 Skill（如 diagnosing-bugs）需另行安装，或由当前 Agent 按描述完成调查。


下面的提示词根据我的规则整理，替换方括号里的内容后即可使用。项目已有更具体的约定时，以当前任务和适用规则为准。

### 想法还模糊时先澄清

```text
我想做［目标与用户场景］。请使用 grill-me / grilling 帮我把需求问清楚。
先读取我已提供的材料；能从仓库查明的事实由你调查。
围绕目标用户、完整使用路径、范围、失败处理和验收标准分轮提问，
每个问题给出推荐答案与理由。
等我确认形成共同理解后，再整理开发文档。
```

### 把讨论收敛为开发依据

```text
请把已经确认的讨论整理成项目开发主文档。
写清目标、范围、业务规则、主要数据和接口、失败处理、阶段与验收标准。
区分已确认事项、待决策事项和后置能力。
如果项目已使用 OpenSpec，请同步本次 proposal、design、specs 和 tasks，
保持与主文档一致，不另建冲突的需求基线。
```

### 执行一个明确阶段

```text
请完成［阶段或子任务］。
先阅读 AGENTS.md、［主文档位置］、对应规格，以及相关代码、测试和配置。
按 karpathy-guidelines 做最小完整修改，保护已有改动。
按已确认的行为补必要测试，运行相关验证，修复本次造成的失败并检查 diff。
同步受影响的规格、README、验收记录和阶段学习说明。
除重大选择或需要额外授权的外部动作外，持续完成当前范围。
最终分别说明实现、验证结果和未验证事项。
```

### 明确采用测试优先

```text
请使用 tdd 实现［行为］。
先提出并确认本次测试入口、预期行为与覆盖边界。
按一个行为、一个失败测试、最小实现使其通过的顺序推进。
断言用户可观察结果，预期值以规格为依据。
完成后运行相关回归，再审查是否需要整理代码。
```

### 建立整体验收测试

```text
请使用 project-testing 审核这个项目。
先读需求、代码、现有测试和配置，输出需求到用例的对应清单，
包括主流程、异常、边界、取消或中断，以及适用的权限与并发场景。
说明测试工具、数据隔离方式和人工待验范围。
本轮先完成清单，等我确认后再实施和运行。
```

### 修复一个具体 Bug

```text
问题是［触发步骤、现象和预期结果］。
先构造能够捕获该症状的最小复现，必要时使用 diagnosing-bugs。
根据实际证据定位根因，再做最小修复和适合的回归测试。
重新运行原始场景与受影响测试，清理临时诊断代码。
说明根因、改动、实际验证结果及剩余限制。
```

### 接续一段开发工作

```text
请先读取 AGENTS.md、交接文档、当前规格和最近验收记录，核对实际代码状态。
整理已完成、未完成、阻塞项和下一项可验收任务，并注明对应证据。
不要把历史计划或旧测试结果自动当成当前完成状态。
在已经明确的范围内继续推进［下一项任务］。
```
