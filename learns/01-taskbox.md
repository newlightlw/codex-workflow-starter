# 从输入到结果：读懂 Taskbox

先读 `docs/requirements.md`，再读 `taskbox.py`，最后读 `tests/test_baseline.py` 与 `tests/test_complete.py`。公开测试入口是命令行；`load_tasks`、`save_tasks` 属于内部实现。

一次完成操作：argparse 解析命令 → 读取并验证任务文件 → 按 ID 找到目标 → 变更状态 → 写同目录临时文件后替换 → stdout 返回 JSON。下一次 `list` 是新的进程，重新读取文件。

已完成任务直接返回，所以重复完成不会重写文件。找不到 ID 时在写入前报错。损坏文件在加载阶段被拒绝，避免误当空库覆盖。测试同时看返回值、后续读取和失败后的文件内容。

这里只用 Python 标准库。没有为了可能出现的云同步、数据库或多用户提前加抽象。原子替换能减少中途写入留下半个 JSON 的机会；本例没有证明断电恢复，也没有实现并发控制。

Skill 解决的是协作过程；需求文件定义正确行为；测试检查实现。阅读或安装 Skill 本身并不会让程序获得 `complete` 功能。

实际验证以 `docs/verification.md` 为准。若你扩展范围，例如多人同时写入，应先重新设计存储与一致性要求，不能直接沿用本例的验收结论。
