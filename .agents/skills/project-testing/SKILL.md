# 项目审核测试

以测试工程师身份，为当前项目建立可重复运行、与真实数据隔离的自动化测试。依据项目实际选择工具，不绑定技术栈。

## 两阶段确认

首次调用完成阶段一后停下，等待用户回复 **“可以开始测试”**，或明确同意当前清单后开始实施。自动进入开发收尾时也保留此确认。

确认前只读调查并输出清单，不写测试、不安装依赖、不运行测试、不改项目文件。一般开发授权不能替代本次清单确认。

同一上下文中已经确认过本技能产出的清单，则直接进入阶段二，不重复确认。重大范围变化需更新清单并确认新增范围；缺少已确认清单时先重建清单供确认。

## 阶段一：调查与用例清单

1. 阅读适用的 AGENTS.md、需求文档、项目说明、相关源码、现有测试、依赖和运行配置。梳理入口、状态变化、持久化及外部服务；检查工作区已有改动并保护它们。
2. 将每条需求规则映射到用例。预期结果以需求为依据；需求与代码冲突或缺少定义时标为待确认，区分事实和推断，不把当前实现直接当成正确行为。没有需求文档时，将从代码提取的行为标为暂定约定。
3. 覆盖以下适用场景：
   - 至少一条从实际入口到最终结果的完整主流程，含关键状态和保存后可读取的结果（如适用）。
   - 每条业务规则、输入校验、错误返回和失败分支。
   - 返回、取消、关闭或中断：检查状态、未保存输入及是否留下副作用。无界面项目映射到实际退出、撤销或中断语义；不适用则说明依据。
   - 空数据、最少有效数据、无效或缺失输入、数量上下限及有代表性的大量数据；涉及分页、排序、批处理时覆盖其边界。
   - 与需求和风险相关的依赖失败、重复提交、权限或并发情况；不编造不存在的功能。
4. 输出清单表格：用例 ID、需求来源（文档章节或代码位置）、场景、前置条件/测试数据、操作步骤、可观察的预期结果、拟用自动化层级或人工验证及原因。每条规则都有用例，或明确标记覆盖缺口、待确认项、不适用原因。
5. 简述拟选工具及理由、隔离方案、自动化入口、已知限制。优先复用现有框架，选择足以验证真实行为的最小工具组合。主流程只能用替身集成验证时，明确未覆盖的真实外部环节。

阶段一结束时说明：**“请确认用例清单；回复‘可以开始测试’后，我再编写并运行测试。”** 明确这是本技能要求的阶段确认，停止实施并等待回复。

## 阶段二：实施与运行

### 数据隔离

- 使用临时目录、专用测试数据库、隔离配置和确定性的合成数据，只清理由测试创建的资源。禁止连接、修改、清空或迁移真实数据库，禁止复制用户真实数据作为 fixture。
- 为拿不到的文件、账号、服务响应自造数据或 mock/stub，覆盖成功与失败分支。测试默认不需要生产密钥，不触发真实支付、发信、发布、上传或通知。
- 运行前检查命令、环境配置和启动钩子实际指向测试资源，确保配置不能意外回退到生产连接；仅变量名不同不算隔离。
- 大量数据采用本地可承受且有业务依据的规模，记录数量。性能阈值应有需求或独立依据，不用任意阈值宣称性能达标。

### 自动化实现

1. 将确认用例实现为适合项目的单元、集成或界面端到端测试。完整主流程穿过实际入口与核心实现，避免整条业务链都被 mock；做不到的部分明确列为缺口。
2. 断言可观察结果、错误信息、关键状态及必要副作用，而非只检查没有报错。数据可重建、时间和随机性可控、测试之间独立；避免固定等待造成不稳定。
3. 提供清楚的本地一次执行入口，支持非交互运行，失败返回非零退出码。按实际需要选依赖和配置，不强制引入新框架或 CI 平台。
4. 亲自运行并追踪失败原因。范围内可修复的问题做最小修改，再跑相关测试与受影响验证。不得跳过用例、降低断言或吞异常制造通过；未解决的失败如实保留并说明原因。

### 文档与后续规则

更新 README 或主要说明文件，写明环境准备、安装命令、测试命令、数据隔离方式、结果查看方法与人工验证范围。较长内容可放独立测试文档，并从项目说明链接过去。

将以下规则写入项目适用的 Agent 指令文件（如 AGENTS.md；没有则建立项目级文件），在项目说明中也列出要求，保留原有指令和用户改动：

> 每次修改代码后，必须运行项目规定的自动化测试，并在回复中报告执行命令、通过/失败/跳过/未执行情况；如无法运行，须说明原因和未验证范围，不得宣称测试通过。

规则引用本次实际建立的测试命令，不留下占位符。

### 最终报告

- 列出交付文件、实际运行命令和结果，分别统计通过、失败、跳过、未执行；失败关联用例 ID 并说明原因。
- 给出需求与用例的最终覆盖情况，区分已实现测试和已运行通过的测试。
- 列出自动化未覆盖或无法证明的事项及原因，提供具体人工操作步骤和预期结果。真实第三方集成、设备行为、视觉体验或生产规模性能，仅在与项目有关时列入。
- 区分合成数据/替身验证与真实环境验收；环境阻塞、跳过或依赖替身不能算真实环境通过。检查最终 diff，确保未夹带真实数据、密钥和无关改动。
