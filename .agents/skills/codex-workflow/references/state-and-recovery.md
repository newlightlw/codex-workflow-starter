# 状态与恢复

## 何时记录

任务跨会话、阶段中断或需要交接时，复用项目已有 HANDOFF/PROGRESS 文件。没有适合入口时，可使用 [STATE.md](../assets/STATE.md)。一次小修改用最终交付说明即可。

状态至少包括需求来源、当前分支/提交、未提交改动归属、最近完成证据、当前步骤、阻塞、下一项可验收任务。计划、实现、自动检查与真人验收分别记录。保存时填写实际记录时间；不能把文件创建时间当作验证时间。

验证记录引用 [VALIDATION.md](../assets/VALIDATION.md) 或已有报告。记录执行时的提交与 dirty 状态、实际命令、环境、通过/失败/跳过/未执行和未覆盖部分。未提交代码的检查需注明覆盖工作区快照，不能只写 HEAD 就声称全部证据绑定该提交。

## 恢复顺序

1. 读取当前指令、需求入口、状态、决策与最近验证记录。
2. 核对实际分支、提交与工作区，区分用户改动和此前任务改动；不重置或清空来“恢复环境”。
3. 交叉核实已完成事项及其证据是否仍适用于当前状态。代码或依赖已变、旧失败未解决时，先运行最相关检查。
4. 修正过时状态，给出下一项可验收任务。在已有授权内继续；关键决策缺失时提出具体问题。

恢复聊天可以带回讨论，但仓库仍需核对。保留同一问题的推理链；只有工作真正分叉或需要不同职责时再考虑分开会话。

## 收敛上下文

保留“目标、决策、当前事实、证据位置、下一步”，把长日志留在实际文件里。按需引用，不把整份设计、日志和历史聊天复制到每个入口。任务结束后保留历史阶段结论；新阶段追加证据，不改写旧记录的时间或验收状态。
