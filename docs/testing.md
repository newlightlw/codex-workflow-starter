# 需求到测试的映射

运行：`python3 -m unittest discover -s tests -v`。测试均使用临时目录；真实执行 CLI 子进程，不 mock 主业务链，不读取个人任务数据，不访问网络。

| 需求 | 自动化观察 | 测试文件 |
| --- | --- | --- |
| R1 | 初次列表为空且不写盘；新增、顺序、ID、跨进程读回 | tests/test_baseline.py |
| R2 | 首尾裁剪、空白拒绝、1/80/81 字符边界及失败后文件不变 | tests/test_baseline.py |
| R3 | 完成后新进程可读；重复完成；其他任务不变 | tests/test_complete.py |
| R4 | 不存在、0、负数 ID；空存储完成失败不建文件 | tests/test_complete.py |
| R5 | 无效 JSON、非法字段/类型/重复 ID/状态；父目录不存在 | tests/test_baseline.py |
| 练习生成 | 新目录基线通过、指定功能断言失败、参考实现替入后通过；已有目录保留 | tests/test_scaffold.py |

`scripts/verify_bundle.py` 另外核对打包的 Skill 文件是否与锁定摘要一致、是否带齐许可证与必需入口。它检查包完整性，不证明 Skill 的行为质量。

## 未覆盖与不适用

R4 的 argparse 参数解析由标准库处理，没有逐项测试其所有错误消息。R5 覆盖代表性读写失败，不穷举 OS 权限、磁盘满、驱动器断开等条件。R6 排除了进程强杀、断电、并发、网络和生产规模性能。

本项目没有 UI 返回/取消、账号权限、分页或外部服务；因此这些项目验收项目不适用。人工检查聚焦使用说明能否跟做、Codex 是否实际读取目标文件、结果是否便于理解。模型回复与技能行为没有被固定期望或自动评分。

## 如何理解练习红灯

根目录全套应通过。练习故意只提供新增/读取基线和一个完成任务失败测试，后续覆盖由读者补齐。`test_scaffold.py` 在隔离目录中断言这次预期失败，再用参考实现检查它确实能转绿；这不是跳过失败，也不代表读者已经完成练习。
