# 第一个小练习：做一张个人介绍网页

目标是让你完成一次“说清需求 → 看见页面 → 检查 → 改一处”的协作。读者只需要能使用 Codex 和浏览器，不需要先学习终端、Python、测试框架或 OpenSpec。

可以先按[轻量接入](quick-start.md)复用项目规则与所需 Skills，也可以直接在空文件夹里做这个小练习。页面内容采用虚构昵称和介绍，按自己的需要替换即可。

## 1. 把下面这段发给 Codex

```text
请在当前项目中新建一个独立的 my-profile-page 文件夹；同名目录存在就换一个新名字，保留原文件。

帮我做一个用浏览器直接打开的中文个人介绍页：
- 昵称：小林。
- 一句话介绍：一个正在学习 AI 的产品人。
- 三张兴趣卡片：AI 工具、产品思考、阅读笔记，每张配一句简短说明。
- 页面简洁清爽，用一个主题色，电脑和手机上都能看清内容。

只用 HTML 和 CSS，页面保存为 index.html，无需安装框架、连接数据库或部署。
先用简短 README 记下需求与验收点，再实现页面并做适合这个小任务的检查。
完成后告诉我打开哪个文件、你实际检查了什么，以及还需要我亲自检查什么。
```

## 2. 打开页面，看三件事

让 Codex 给出生成文件的准确路径，用浏览器打开其中的 `index.html`。若当前客户端支持文件链接，可以直接点击；否则在文件夹中找到它，再选择用浏览器打开。

1. 昵称、介绍和三张卡片是否齐全，内容是否符合需求？
2. 缩窄浏览器窗口模拟手机宽度后，文字是否重叠，页面是否需要左右拖动？
3. 页面在本地是否能直接打开，是否意外依赖安装工具或外部服务？

浏览器缩窄检查不等于真机验证。Codex 如果有浏览器能力，可以补充自动检查并记录实际范围；没有时应列为人工检查，不把截图或检查结果编出来。

## 3. 再提一个小修改

```text
把刚才页面的主题色改成绿色，其他内容和布局保持不变。
修改后核对影响范围，并告诉我刷新哪个页面查看结果。
```

刷新页面，确认颜色变了，昵称、简介、卡片内容和布局仍然正确。再看一次文件改动，体验一次范围明确的小迭代。

这份练习提供需求、提示词和验收办法；不附生成后的固定页面。不同 Codex 环境的视觉结果可能不同，以需求和实际检查为准。本文不把它记作跨客户端实测成功。

想进一步练习自动化测试、失败到通过和规格管理，再使用 [Taskbox 进阶练习](start-here.md)。
