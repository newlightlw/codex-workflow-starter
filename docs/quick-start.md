# 把仓库地址交给 Codex，复用这套方法

先在 Codex 中打开你自己的项目。没有项目，可以新建一个空文件夹，例如 `my-first-project`，将它作为项目打开。接着复制下面整段提示词；下载、检查文件和接入步骤交给 Codex 完成。

```text
参考仓库：https://github.com/newlightlw/codex-workflow-starter

请把这套 Codex 工作方法接入当前项目。
1. 先读取仓库 README、docs/adoption.md、docs/skills.md，再检查当前项目已有规则与 Skills。
2. 优先接入 codex-workflow 和 karpathy-guidelines；已有同名能力时先比较、复用，保留来源版本、许可与完整支持文件，不覆盖已有配置。其他 Skills 按需要再加。
3. 将按需使用约定合并进本项目 AGENTS.md：复杂任务按 codex-workflow 组织；编码时遵循 karpathy-guidelines；简单修改直接做，文档和验证按任务规模安排。
4. 本轮只接入工作方法，不复制 Taskbox 业务代码，不修改全局配置。能在本地完成的接入请直接做；无法访问仓库、无法写入或遇到规则冲突时，说明具体问题。
5. 完成后列出实际新增或修改的文件、已读取的 Skill 路径、未验证项，并告诉我接下来怎样提一个小需求。
```

这是一条项目级的轻量接入路线。仓库访问和文件写入依赖读者自己的 Codex 环境与权限；没有相关能力时，Codex 应说明阻塞位置。不要把“计划复制”记成“已接入”。

## 接入完成后看什么

- **文件确实存在**：新增 Skill 的具体位置、已有 Skill 的复用情况，以及 AGENTS.md 的实际改动。
- **规则没有丢失**：保留原项目约定；冲突指出并解决，同名 Skill 不静默覆盖。
- **调用有依据**：报告实际读取的 Skill 路径。文件已复制、文件已读取与新会话按场景自动使用，是不同的验证事项。

随后可以直接提一个具体任务，参照[个人介绍页练习](first-page.md)。小任务沿用简单流程；需求不清再加入 `grill-me`，需要测试驱动开发再加入 `tdd`。本路线不要求一次装齐所有 Skills。

## 给执行接入的 Codex 的说明

本仓库作为来源，目标是读者当前打开的项目。将下载材料与目标项目区分开，记录来源提交或发布版本，不将模板占位内容当成目标项目事实。

`scripts/adopt_workflow.py` 只接入 `codex-workflow`。按[接入说明](adoption.md)先预览、检查冲突，再按这条提示词已有授权应用；若环境不支持脚本，也可以按同样范围复制完整目录及许可，但不要声称脚本已经运行。

`karpathy-guidelines` 需要单独复制完整目录，并保留对应的第三方许可证、来源声明及 `skills-lock.json` 中的来源与摘要信息。相关原件见 `LICENSES/`、`THIRD_PARTY_NOTICES.md`。目标已有这些文件时，单独保存这份来源资料或合并必要条目，不能覆盖原内容。

AGENTS.md 的按需规则由 Codex 根据原项目约定合并；接入脚本本身不会修改它。不要为了接入工作流改业务实现、安装应用依赖或向全局目录写入。

此提示词是操作引导，尚未完成跨客户端的独立新手复现实验。接入脚本的隔离验证与作者实际项目案例见[验证记录](verification.md)和[案例页](case-project-continuation.md)。
