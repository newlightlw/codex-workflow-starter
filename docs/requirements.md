# Taskbox 开发依据

状态：本仓库根目录是完整参考实现。所有要求针对本地单用户顺序执行的 CLI。

## 目标与范围

读者从命令行新增任务、查看列表、标记任务完成，并在下一次进程中读到结果。持久化是本地 UTF-8 JSON 文件。默认 `.taskbox.json`，支持在子命令前提供 `--store PATH`。

## R1 新建与读取

不存在的文件表示空列表；`list` 返回 `[]`，不会创建文件。新增按输入顺序返回递增的正整数 ID（首个为 1）、标题与 `pending` 状态。成功 stdout 输出 JSON，退出码 0，stderr 为空。

## R2 标题

新增先移除标题首尾空白，再校验长度为 1–80 个 Python 字符串字符（Unicode code point，非字节/字形数）。保留中间空白。空白标题或 81 字符输入返回错误，不改变已有文件；首次失败不创建文件。

## R3 完成任务

`complete ID` 将存在的任务从 `pending` 改成 `completed`，返回该任务。后续独立 `list` 进程应读到完成状态。其他任务的 ID、标题、状态与顺序保持原样。重复完成同一任务成功返回原有结果，文件内容不变。新增仍为 `pending`。

## R4 不存在的任务

整数 ID 不存在（包括 0 和负数）时返回 `task not found`，退出码 2。保留已有文件；文件不存在时仍不创建。非整数及缺失参数由 argparse 报命令用法错误，退出码 2，这类解析错误是文本而非 JSON。

## R5 文件错误

已存在文件必须为任务数组，每项只含 `id/title/status`，ID 为唯一正整数，标题符合 R2，状态只能是 `pending/completed`。JSON 损坏、结构非法或读写失败时：stderr 输出 JSON 错误，退出码 2，stdout 为空。不得将损坏内容当作空列表覆盖。目标父目录不存在时报错，不自动创建目录。

## R6 范围与验收边界

使用临时目录和合成数据，从真实 CLI 入口到持久化，再由新进程读回验证。无网络、外部账号、登录、删除、编辑、取消、分页或多进程并发写入。可预期的命令失败不得改变既有数据；进程被强制终止、磁盘断电、文件系统耐久性、恶意符号链接和并发竞争不在验收范围。原子替换有助于减少部分写入，但不等于证明上述故障恢复。

## 变更控制

改变 R1–R6 前先确认新行为，再同步 OpenSpec、测试与运行说明。`docs/testing.md` 维护需求到验证的映射。
