# 把工作流接入自己的项目

v0.2.0 增加独立的 `codex-workflow` Skill。它封装项目接入、任务定义、状态恢复、审查与交付流程，附带支持文件和模板。原有 6 个专项 Skills 继续保留。

作者后续已通过用户级安装在真实项目使用该 Skill，见 v0.2.1 的[使用案例](case-deepagents-imp.md)。案例不等于本节接入脚本已在该项目运行；脚本的验证仍来自隔离测试。

## 路线 A：在本仓库或生成的练习中使用

在 Codex 中打开对应目录，开始新会话，明确要求读取项目中的 `.agents/skills/codex-workflow/SKILL.md`。支持技能选择器的客户端可用 `$codex-workflow`。检查实际读取路径；同名全局技能可能同时存在。

## 路线 B：接入已有项目

在 starter 仓库根目录执行，替换目标目录为自己的实际路径：

```bash
python3 scripts/adopt_workflow.py /path/to/your-project
```

默认只读预览，列出源文件、目标位置和冲突，不创建目录。确认预览内容符合预期后运行：

```bash
python3 scripts/adopt_workflow.py /path/to/your-project --apply
```

仅新增 `<目标项目>/.agents/skills/codex-workflow/`，复制完整 Skill、模板和 MIT 许可；不需要网络、额外 Python 包或其他 Skills。目标必须已存在；同名 Skill、目标路径上的符号链接或不合法目录会报错，不覆盖旧内容。再次执行也会拒绝覆盖；升级时应先比较差异，再由自己决定如何合并。

工具不会合并 AGENTS.md、修改配置或创建 Git 仓库。应用后的下一步是：

```text
请读取本项目 .agents/skills/codex-workflow/SKILL.md，按“项目接入”分支处理。
先核对现有 AGENTS.md、README、需求、相关代码、测试和配置。
给出项目地图、已验证的命令入口与需要补充的文档位置。
本轮先完成只读调查；不要把模板中的占位文字写成项目事实。
```

要在后续任务中实施，直接补充明确目标和授权范围。只读接入这一轮的限制不要求所有未来任务都暂停确认。

## 接续现有任务

```text
使用本项目 codex-workflow 的恢复分支。
先读已有交接与验证记录，核对实际分支、提交和未提交改动。
区分仍成立的已完成事项、过期证据和下一项可验收任务。
在已授权范围内继续当前任务，保留用户已有改动。
```

已有 OpenSpec、ADR、TASKS 或 HANDOFF 时优先引用，不另外造一套重复状态。模板在 Skill 的 `assets/`，按缺口选用。

## 全局使用

默认提供项目级接入。若你明确希望所有项目都可发现，可按当前[官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)将完整 `codex-workflow` 文件夹安装到自己的用户级技能位置（目前为 `~/.agents/skills/`），保留许可证与支持文件，并检查同名版本。本文工具不写全局目录，也不更改你的既有全局指令。

## 接入工具的行为约定

| ID | 行为 |
| --- | --- |
| A1 | 默认预览不改变目标项目，即使包含现有 AGENTS、配置和用户文件 |
| A2 | `--apply` 仅安装完整独立 Skill，保留既有文件与其他 Skills |
| A3 | 目标不存在、已有同名目录、路径阻塞、符号链接时非零退出且不开始复制 |
| A4 | 目标路径包含空格/中文可用；成功后从 Skill 相对路径可找到全部支持文件 |

自动化验证通过真实命令、临时项目与预置文件检查这些行为，见 `tests/test_adoption.py`。不覆盖安装过程中其他进程恶意竞争、断电或所有操作系统故障；不是并发部署工具。

若复制中途发生 I/O 错误，可能留下不完整的新 Skill 目录；先检查后处理，工具不自动删除它。A3 描述的是复制开始前的路径检查，不是事务回滚保证。
