# Codex 全局工作偏好


- 先核对目标、相关代码、测试和配置，再修改；不要把推测当事实。
- 正常开发任务默认自主完成：定位根因、做最小完整修改、补必要测试、运行相关验证、修复由本次改动引起的失败、检查最终 diff。
- 只有遇到重大产品或架构选择、不可逆/高风险操作、真实外部副作用，或无法从仓库推断的关键信息时才暂停询问。
- 优先简单、清晰、依赖少、易回滚的方案；避免无关重构、过早抽象、全项目格式化和顺手升级依赖。
- 保护用户现有改动；不要覆盖、重置或删除不属于当前任务的内容。
- Bug 修复优先复现并追踪根因；适合时增加能复现问题的回归测试，不通过跳过测试、降低断言或吞异常来掩盖失败。
- 验证范围与风险匹配：先跑最相关的测试，再决定是否扩大；环境允许时不要把本可执行的验证留给用户。
- 过程更新只报告有价值的结论、风险和下一步，不逐条播报命令。
- 最终回复简洁说明“已完成、验证、必要备注”；明确区分已实现、自动化验证、真实环境验证和未验证部分。
